# `src/dev/` — Development and validation tooling

Tools for diagnosing and measuring retrieval and ingestion quality. **Not part
of the production runtime**: nothing in this directory is imported from the
app, except `src/dev-tools.ts`, which is only loaded with
`import.meta.env.DEV`.

## Structure

### `benchmarks/search/`

Search benchmarks: hybrid (vector + text), cross-encoder,
nDCG / Hit / Recall metrics over ground truth, and targeted diagnostics. The
heavy benchmarks are hidden behind environment variables (see Commands).

Key files:

- `hybrid-benchmark.test.ts` — hybrid search over the Britney corpus.
- `cross-encoder-benchmark.test.ts` — cross-encoder.
- `qasper-benchmark.test.ts` — multi-document retrieval over QASPER.
- `first-album-diagnostic.test.ts`, `reranker-diagnostic.test.ts` —
  one-off diagnostics.
- `search-benchmark.*.ts` — runner, evaluation, nDCG, datasets, types.

### `benchmarks/ingest/`

Ingestion and chunking diagnostics: overlap, links (cross-references),
chunk sizes, token counts and a measurement baseline. They require no
environment variables; they run with the normal suite.

### `corpus/`

- `corpus-export.service.ts` — exports a complete library from Dexie to a
  JSON fixture (documents, chunks and optional embeddings).
- `corpus-fixture.loader.ts` — loads offline fixtures for the benchmarks. If
  the fixture does not exist, the loader returns `null` and the suites that
  need it `skip` (they do not fail).

### `fixtures/`

Versioned test corpora:

- `britnet-corpus.json` — corpus of the Britney library (uses the first
  album), with ground truth for the search benchmarks.
- `qasper-1908_06606.md`, `qasper-1910_11471.md` — QASPER papers. See
  `fixtures/README.md` for attribution and detail.

The caches generated by the benchmarks (`.embedding-cache/`,
`.qasper-cache/`) **are not versioned**: they are in `.gitignore` because they
are reproducible artifacts.

### `src/dev-tools.ts`

Console tools available **in development only**, exposed as
`window.__rag`:

- `__rag.listLibraries()` — table of libraries with their IDs (needed to
  export).
- `__rag.exportCorpus(id, options)` — exports the corpus of a library.
  `options.includeEmbeddings` (defaults to `true`) allows omitting embeddings.

## Usage from the browser console

```js
await __rag.listLibraries()
await __rag.exportCorpus('LIBRARY_ID')
await __rag.exportCorpus('LIBRARY_ID', { includeEmbeddings: false })
```

The export triggers a JSON download
(`rag-corpus-<libraryId>-<date>.json`). Move that file to
`src/dev/fixtures/` so the benchmarks can consume it.

## Commands

### Verification

```bash
npm run typecheck
npx vitest run
npm run build
```

### Benchmarks and diagnostics (disabled by default)

```bash
HYBRID_BENCHMARK=1 npx vitest run --environment node --reporter=verbose src/dev/benchmarks/search/hybrid-benchmark.test.ts
CROSS_ENCODER_BENCHMARK=1 npx vitest run --environment node --reporter=verbose src/dev/benchmarks/search/cross-encoder-benchmark.test.ts
QASPER_BENCHMARK=1 npx vitest run --environment node --reporter=verbose src/dev/benchmarks/search/qasper-benchmark.test.ts
FIRST_ALBUM_DIAGNOSTIC=1 npx vitest run --environment node --reporter=verbose src/dev/benchmarks/search/first-album-diagnostic.test.ts
RERANKER_DIAGNOSTIC=1 npx vitest run --environment node --reporter=verbose src/dev/benchmarks/search/reranker-diagnostic.test.ts
```

Without its environment variable, each of these suites is skipped via
`describe.skipIf`, so a quick `npx vitest run` never executes them.

## Benchmark caches

The heavy benchmarks download models and generate caches in:

- `src/dev/fixtures/.embedding-cache/` — embeddings of chunks and queries.
- `src/dev/fixtures/.qasper-cache/` — embeddings of the QASPER papers.

Both are ignored by Git. **If the chunking or the embedding model changes,
delete them before measuring**, because the metrics would otherwise be
distorted by stale embeddings:

```bash
rm -rf src/dev/fixtures/.embedding-cache src/dev/fixtures/.qasper-cache
```

## Fixture dependency

The Britney and QASPER benchmarks need the fixtures in
`src/dev/fixtures/`. If a fixture is missing, the tests that consume it
`skip` instead of failing: check that the file exists before interpreting
an empty result.
